# 08 · 이행점검 (Reverify)

> 사이드바 **결과 > 이행점검** · 소스 `frontend/src/pages/Reverify.tsx` · 재점검 실행은 `scan:run` 권한

이전에 도출된 취약 항목의 **조치 여부를 재점검**하고, 스캔 간 공격면 변화를 비교하는 페이지입니다.
§5.5·FR-5.x에 대응합니다.

## 화면 구성

- **이행점검 실행 (ReverifyControl)** — 재점검 대상(오탐 제외 finding) 수 표시, `취약 항목 재점검`
  버튼으로 이전 취약 finding을 **replay·재평가**해 조치 여부 판정. 아래에 전체 이행 현황 세그먼트 바
  (조치완료/미조치/부분조치/신규발생/미점검)
- **스캔 간 변화 (DiffCard, FR-5.4)** — 두 ScanRun을 `from → to`로 선택(기본: 최신 두 개 자동).
  **신규(added) / 소멸(removed) / 공통** finding을 나란히 표시
- **이행점검 실행 이력** — 실행별 카드: 조치율 바(조치완료/미조치/미확인), 결과 테이블
  (Finding·취약점·대상·탐지기·**판정**·상세). 미조치·신규발생을 위로 정렬·강조

## 판정(verdict) 의미

| 판정 | 뜻 |
|---|---|
| 조치완료 | 재점검 시 재현 안 됨 |
| 미조치 | 여전히 재현 |
| 부분조치 | 일부만 해소 |
| 신규발생 | 이전엔 없던 취약 |
| 미확인 | 재평가 불가 |

## 주요 액션 → API

| 액션 | 엔드포인트 | 비고 |
|---|---|---|
| 재점검 실행 | `POST /api/reverify` | `scan:run`, 오탐 제외 replay·재평가 |
| 스캔 diff | `GET /api/scan-diff?from=&to=` | |

조회: `GET /api/reverify` · `GET /api/scanruns` · `GET /api/findings`

## 동작 메모
- 이행점검 실행 결과(run)는 **인메모리**입니다(미영속). 이행상태는 finding의 `reverify_status`에 반영.
