# 03 · 정찰 / 대상 파악 (Recon)

> 사이드바 **진단 > 정찰** · 소스 `frontend/src/pages/Recon.tsx` · 크롤 실행은 `scan:run` 권한, 로그인 시퀀스 저장은 리더 전용

진단 대상의 **공격면(엔드포인트)**을 파악하고, 스코프·인증·판단 파이프라인 현황을 확인하는
페이지입니다. 요구사항 §5.2(대상 파악)·FR-2.x에 대응합니다.

## 화면 구성

**좌측 (2/3)**
- **프록시 도구** — 공용 프록시(:8080) 상태(리슨 주소·**캡처 on/off 배지**·누적 캡처 수·수집
  엔드포인트/호스트·스코프 호스트)와 **캡처 토글**(리더 `proxy:control`, 무권한 시 비활성),
  **CA 신뢰 상태**(미신뢰 시 `-cert-install` 명령 안내)·브라우저 프록시·**트래픽 유도 `curl`**
  가이드를 한 카드에 모음. 캡처가 꺼져 있으면 "Endpoint Tree가 안 채워짐" 경고. 기존 API만 사용(이슈 #9)
- **자동 크롤 (Explore)** — 시작 URL에서 링크·폼·JS 번들을 따라 스코프 내를 BFS 크롤(AppScan
  Explore 대응). 비파괴(GET·폼 등록만). 정적 추출 기본, **헤드리스(Chrome, JS 실행) 옵트인**
  (서버에 Chrome 없으면 비활성). 실행 상태·발견 수·JS 번들 수 표시
- **Endpoint Tree** — 호스트별로 그룹된 캡처 엔드포인트. 메서드·경로·인증 필요 표식·판정 배지·히트 수.
  **검색(호스트·경로)·메서드·인증·판정 필터**로 좁히고, 행을 클릭하면 **상세**가 펼쳐진다 —
  파라미터 표(위치 `query/body/json/file` · 이름 · 타입 · 필수 · 샘플[마스킹]) · 히트 수 ·
  **최초/최근 발견 시각**. 프록시(:8080) 경유 트래픽으로도 채워짐(캡처는 런타임에 on/off 가능
  — 아래 **프록시 캡처 제어**)

**우측 (1/3)**
- **Judgment Pipeline** — 스코프 → Rule → LLM → Forward 단계 시각화 + 활성 룰 목록(block/allow)
- **Scope (whitelist)** — 허용 스코프 목록
- **Auth & Identities** — 세션 주입 On/Off, 주입 쿠키/헤더, 등록된 진단 신원(수평/수직 접근통제 대조용)
- **로그인 시퀀스 (세션 지속성, FR-2.5)** — 긴 스캔 중 세션 만료 시 자동 재로그인 절차 설정.
  로그인 URL·**만료 표식(정규식, 있어야 활성화)**·폼 필드·CSRF 토큰. 값은 마스킹, 저장은 리더 전용,
  비밀번호는 응답 미노출·인메모리 주입기에만 반영

## 주요 액션 → API

| 액션 | 엔드포인트 | 비고 |
|---|---|---|
| 크롤 시작 | `POST /api/crawl` (`mode: static\|headless`) | `scan:run` |
| 헤드리스 가용성 | `GET /api/crawl-modes` | |
| 로그인 시퀀스 저장 | `POST /api/login-seq` | 리더, 감사 기록 |
| 프록시 캡처 on/off | `POST /api/proxy/capture` (`on`) | 리더(`proxy:control`), 감사 기록 |

조회: `/api/endpoints` · `/api/proxy` · `/api/rules` · `/api/stats` · `/api/auth` · `/api/login-seq` · `/api/crawl`

### 엔드포인트 조회 API (이슈 #7)
- `GET /api/endpoints` — 필터·검색·페이징: `host`(부분일치)·`method`·`verdict`(부분일치)·
  `auth`(true/false)·`q`(host+path 검색)·`limit`/`offset`. 전체 개수는 **`X-Total-Count`** 헤더.
  **무필터·무페이징이면 기존과 동일한 전체 배열**(하위호환)
- `GET /api/endpoints/tree` — 풍부한 트리(`Snapshot`): verdict·hit count·children·params
- `GET /api/endpoints/detail?host=&path=` — 단일 엔드포인트 상세(concrete path 도 정규화해 조회):
  메서드·파라미터·히트 수·판정·**최초/최근 발견 시각**

> 발견 시각(`first_seen`/`last_seen`)은 엔드포인트 모델에 저장되고 `endpoints.json`에 영속화된다
> (재시작 후에도 유지). 현재 UI 필터는 클라이언트 측에서 즉시 반영되며, 위 서버측 필터는 API·프로그램틱 조회용이다.

## 프록시 캡처 제어 (공용 :8080)

공용 프록시는 항상 켜져 있고, **엔드포인트 캡처(공격면 기록)만 런타임에 on/off** 합니다
(프로세스·스코프·인증·판단 파이프라인은 영향 없음). 캡처를 끄면 트래픽은 그대로 통과하되
`endpoints.json`에 새 엔드포인트가 기록되지 않고, 다시 켜면 재개됩니다.

- **상태 조회** `GET /api/proxy` — 리슨 주소·캡처 여부·스코프 호스트 수·누적 캡처 수·공격면 규모
- **캡처 토글** `POST /api/proxy/capture` `{on}` — 리더(`proxy:control`), 감사 기록
- **MCP** `proxy_status`(조회) · `set_capture`(토글, 리더) — 외부 에이전트용
- 테넌트 전용 프록시([02-프로젝트](02-프로젝트.md))는 이 토글의 영향을 받지 않습니다(격리 유지)

> GUI 연동 완료(이슈 #9) — 위 상태·토글은 정찰 페이지 좌측 **프록시 도구** 카드에서 바로 쓸 수 있고,
> API·MCP로도 동일하게 제공됩니다. (CA 설치는 OS 신뢰저장소 변경이라 웹에서 실행 불가 → 명령 안내로 제공)

## 스펙 인제스터 (이슈 #25)

링크를 따라가는 크롤만으로는 **링크가 없는 API**를 찾을 수 없습니다. VAmPI 같은 순수 REST API는
크롤 재현율이 0%였습니다. 인제스터는 대상이 **스스로 공개하는 명세**를 읽어 엔드포인트를 얻습니다
(`backend/internal/recon/ingest/`). OpenAPI 한 파일이면 수백 페이지 크롤보다 정확한
경로·메서드·파라미터·타입을 한 번에 줍니다. Chrome이 필요 없어 **폐쇄망 정적 SPA 대응의 핵심**이기도 합니다.

| 수집기 | 대상 | 얻는 것 |
|---|---|---|
| robots.txt | `/robots.txt` | `Allow`/`Disallow` 경로 (와일드카드 규칙 제외) |
| sitemap.xml | robots의 `Sitemap:` 또는 `/sitemap.xml` | `<loc>` 경로. `sitemapindex` 중첩 재귀(깊이 3) |
| OpenAPI/Swagger | 후보 8종 프로브 | paths·methods·parameters·requestBody (타입·required 포함) |
| GraphQL | `/graphql` 계열 3종 | introspection 성공 시 경로를 공격면으로 등록 |
| 소스맵 | `<script src>` + `.map` | `sourcesContent`에서 API 경로 재추출 |

전부 **GET only·비파괴**이며 스코프(FR-2.1)로 하드 게이트하고, 크롤러와 같은 120ms 레이트리밋과
인증 주입(FR-2.5)을 씁니다. 등록은 `endpoints.RecordSpec`으로 하여 **출처 `spec`** 태그가 붙습니다.

### 상태코드로 판정하지 않습니다

SPA는 **없는 경로에도 `index.html`을 200으로** 돌려줍니다. Juice Shop 실측:

```
/openapi.json                -> code=200 type=text/html size=9393
/swagger.json                -> code=200 type=text/html size=9393
/graphql                     -> code=200 type=text/html size=9393
nonexistent-bogus-xyz.js.map -> code=200 type=text/html size=9393
```

상태코드만 보면 **없는 명세 4개를 "발견"하고 HTML을 파싱하려 듭니다.** 인제스터는 content-type과
본문의 필수 키까지 확인합니다 — OpenAPI는 `paths` + 버전 표식(`openapi`/`swagger`), GraphQL은
`data.__schema`, 소스맵은 `version` + `sources`. 걸러낸 후보는 `Report.Rejected`에 남아
"검증이 실제로 동작했다"를 확인할 수 있습니다.

소스맵 발견도 `sourceMappingURL` 주석에 의존하지 않습니다. Juice Shop 번들은 그 주석이 제거돼 있어
주석만 믿으면 하나도 못 찾습니다. 주석이 있으면 우선하고, 없으면 **`<번들>.map` 관례로 프로브**합니다.

### 명세 경로와 크롤 경로는 한 노드로 합쳐집니다

명세는 `/users/v1/{username}`을, 크롤은 `/users/v1/alice`를 등록합니다. 그대로 두면 같은 엔드포인트가
노드 2개로 갈라져 트리가 중복 계상되고, 크롤 쪽 노드는 `source=spec` 태그를 못 받습니다.

`RecordSpec`이 경로에서 `{name}` 세그먼트를 만나면 **그 자리를 "변수 자리"로 선언**합니다
(아래 경로 정규화 v2 절의 형제 클러스터링과 같은 흡수 메커니즘). 이후 크롤이 같은 자리에 구체값을
기록하면 별도 노드를 만들지 않고 흡수됩니다.

흡수 규칙은 세 가지를 지킵니다.

- **리터럴 우선.** 명세가 `{username}`과 `_debug`·`register`·`login`을 함께 등록했을 때, 크롤이 만난
  `/users/v1/_debug`가 `{username}`으로 삼켜지면 안 됩니다.
- **명세 선언 자리는 값 모양을 따지지 않습니다.** 휴리스틱(#24)은 숫자·구분자가 있는 세그먼트만
  흡수하지만, 명세는 확정 정보이므로 `alice`도 흡수합니다.
- **명세 기록 자신은 흡수되지 않습니다.** 명세가 트리 구조의 기준입니다.

### 언제 도는가

크롤(`static`/`headless`)을 시작하면 **seed 호스트에 대해 1회 자동 인제스트**합니다. 링크를 따라가기
전에 명세를 먼저 확보해야 이후 크롤이 만나는 구체값이 변수 자리로 흡수됩니다. `Options.NoIngest`로 끌 수 있습니다.

벤치 하네스에는 **`ingest` 프로파일**이 따로 있습니다. 크롤을 돌리지 않아 "명세만으로 얼마나 찾는가"가
그대로 측정됩니다. 실측 결과는 `docs/recon-groundtruth/README.md`를 보세요.

재현:

```bash
cd backend && go test ./internal/recon/ingest -v
```

## 경로 정규화 (v2, 이슈 #24)

같은 엔드포인트가 값만 다른 수백 개 노드로 쪼개지면 트리가 폭발하고 스캔 타겟·커버리지
지표가 오염됩니다. Endpoint Tree는 경로를 기록하기 전에 **가변 세그먼트를 템플릿으로 접습니다**
(`backend/internal/endpoints/normalize.go`).

| 입력 세그먼트 | 접힌 결과 | 예 |
|---|---|---|
| 숫자만 | `{id}` | `/user/42` → `/user/{id}` |
| UUID (8-4-4-4-12) | `{uuid}` | `/u/550e8400-…-446655440000` → `/u/{uuid}` |
| hex 16자 이상 | `{hash}` | `/t/0123456789abcdef0123` → `/t/{hash}` |
| `YYYY-MM-DD` | `{date}` | `/logs/2026-08-18` → `/logs/{date}` |
| base64-ish (20자↑·숫자·대문자) | `{b64}` | `/t/eyJhbGciOiJIUzI1NiJ9` → `/t/{b64}` |

- **확장자는 보존**하고 파일명 안의 해시만 접습니다 — `/assets/main.9f8a7b6c5d4e3f21.js` → `/assets/main.{hash}.js` (웹팩 번들 해시).
- hex는 **16자 이상**만 변수로 봅니다. `/x/cafe` 같은 짧은 hex는 실단어일 수 있어 보존합니다.
- base64는 소문자 slug(`application-configuration`)와 구분하려고 숫자·대문자를 함께 요구합니다.

### 형제 다양성 클러스터링

같은 부모 밑에 값처럼 생긴 리프가 **12개 이상** 쌓이고 **고유비율이 0.8 이상**(대부분 1회만 등장)이면
그 자리는 라우트명이 아니라 값이라고 보고 `{slug}` 하나로 병합합니다. 한 번 접힌 자리는 이후 값을
바로 흡수해 재팽창을 막습니다.

접기 대상에서 **제외**되는 것 — 재현율(공격면 누락)을 보호하기 위한 보수적 경계입니다.

- **호스트 루트 직속 자식**. 루트 세그먼트는 대개 최상위 라우트명이라, 접히면 `/metrics` 같은 실제 엔드포인트가 통째로 사라집니다.
- **파라미터가 있는 노드**. 공격면 자체이므로 보존합니다.
- **하위 구조가 있는 노드**. 리프만 후보입니다.
- **값처럼 생기지 않은 세그먼트**. 숫자를 포함하거나 단어 구분자(`-` `_`)가 2개 이상인 것만 후보입니다. 라우트명은 대개 한 단어이거나 하이픈 하나로 이어진 짧은 명사구입니다 (`Products`, `SecurityQuestions`, `application-configuration`, `reset-password`).

> **이 가드가 없으면 REST 리소스 컬렉션이 통째로 사라집니다.** Juice Shop `/api` 밑에는
> `Products`·`Feedbacks`·`Challenges` 등 12종 이상이 각각 1회씩만 등장하는 리프로 쌓입니다.
> "리프 + 무파라미터 + 고유비율 높음"만으로는 이들이 slug 값과 구분되지 않아 `/api/{slug}` 하나로
> 접혔고, 하네스 재현율이 41.9% → 22.6%로 무너진 적이 있습니다.

### 하위호환

v1(숫자만 접던 시절)로 저장된 `endpoints.json`은 **로드 시 1회 재분류·병합**됩니다. 같은 템플릿이 된
노드는 히트 수(`count`)와 파라미터 등장 수(`seen`)를 합산해 `Required`(= `seen == count`) 정합을
유지하고, 재요청용 구체 경로는 더 최근에 본 쪽을 남깁니다. 파일은 다음 캡처 때 자연히 갱신됩니다.

`Param.Type`의 반환 집합은 v1 그대로입니다(`int|bool|uuid|email|string`) — 분류 **규칙**만
공유하고 저장·표시 계약은 바꾸지 않습니다.

재현:

```bash
cd backend && go test ./internal/endpoints -run Normalize -v
```
