# 03 · 정찰 / 대상 파악 (Recon)

> 사이드바 **진단 > 정찰** · 소스 `frontend/src/pages/Recon.tsx` · 크롤 실행은 `scan:run` 권한, 로그인 시퀀스 저장은 리더 전용

진단 대상의 **공격면(엔드포인트)**을 파악하고, 스코프·인증·판단 파이프라인 현황을 확인하는
페이지입니다. 요구사항 §5.2(대상 파악)·FR-2.x에 대응합니다.

## 화면 구성

**좌측 (2/3)**
- **프록시 도구** — 공용 프록시(:8080) 상태(리슨 주소·**캡처 on/off 배지**·누적 캡처 수·수집
  엔드포인트/호스트·스코프 호스트)와 **캡처 토글**(리더 `proxy:control`, 무권한 시 비활성),
  **CA 신뢰 상태**(미신뢰 시 `-cert-install` 명령 안내)·브라우저 프록시·**트래픽 유도 `curl`**
  가이드를 한 카드에 모음. 캡처가 꺼져 있으면 "Endpoint Tree가 안 채워짐" 경고. 기존 API만 사용(이슈 #9)
- **자동 크롤 (Explore)** — 시작 URL에서 링크·폼·JS 번들을 따라 스코프 내를 BFS 크롤(AppScan
  Explore 대응). 비파괴(GET·폼 등록만). 정적 추출 기본, **헤드리스(Chrome, JS 실행) 옵트인**
  (서버에 Chrome 없으면 비활성). 실행 상태·발견 수·JS 번들 수 표시
- **Endpoint Tree** — 호스트별로 그룹된 캡처 엔드포인트. 메서드·경로·**소스 배지**·인증 필요 표식·판정 배지·히트 수.
  **검색(호스트·경로)·메서드·인증·판정·미검증 필터**로 좁히고, 행을 클릭하면 **상세**가 펼쳐진다 —
  파라미터 표(위치 `query/body/json/file` · 이름 · 타입 · 필수 · 샘플[마스킹]) · 히트 수 ·
  **최초/최근 발견 시각**. 프록시(:8080) 경유 트래픽으로도 채워짐(캡처는 런타임에 on/off 가능
  — 아래 **프록시 캡처 제어**)
  - **소스 배지**(이슈 #28) — 각 엔드포인트를 **어디서 알게 됐는지**를 신뢰도 색으로 표시한다:
    `spec`(명세, 녹색) · `traffic`(실캡처) · `xhr`(헤드리스) · `discover`(능동 발견, 보라) ·
    `crawl`(링크 추종) · `regex`(정규식 추출, 회색). 필터 바 아래에 **출처 분포**(등급별 카운트)와
    **미검증 수**를 요약한다. 실운영엔 정답셋이 없어 P/R/F1 대신 이 분포로 커버리지를 가늠한다.
  - **미검증 필터**(이슈 #26·#28) — 라이브니스 프로브(soft-404)를 통과하지 못한 엔드포인트는
    **기본 숨김**이다. 미검증이 있을 때만 `미검증 (N)` 토글이 나오고, 켜면 `unverified` 배지와 함께
    노출된다. API 는 `GET /api/endpoints?include_unverified=true` 로 전체를 받는다(무파라미터는
    verified 만 — 하위호환).

**우측 (1/3)**
- **Judgment Pipeline** — 스코프 → Rule → LLM → Forward 단계 시각화 + 활성 룰 목록(block/allow)
- **Scope (whitelist)** — 허용 스코프 목록
- **Auth & Identities** — 세션 주입 On/Off, 주입 쿠키/헤더, 등록된 진단 신원(수평/수직 접근통제 대조용)
- **로그인 시퀀스 (세션 지속성, FR-2.5)** — 긴 스캔 중 세션 만료 시 자동 재로그인 절차 설정.
  로그인 URL·**만료 표식(정규식, 있어야 활성화)**·폼 필드·CSRF 토큰. 값은 마스킹, 저장은 리더 전용,
  비밀번호는 응답 미노출·인메모리 주입기에만 반영

## 주요 액션 → API

| 액션 | 엔드포인트 | 비고 |
|---|---|---|
| 크롤 시작 | `POST /api/crawl` (`mode: static\|headless`) | `scan:run` |
| 헤드리스 가용성 | `GET /api/crawl-modes` | |
| 로그인 시퀀스 저장 | `POST /api/login-seq` | 리더, 감사 기록 |
| 프록시 캡처 on/off | `POST /api/proxy/capture` (`on`) | 리더(`proxy:control`), 감사 기록 |

조회: `/api/endpoints` · `/api/proxy` · `/api/rules` · `/api/stats` · `/api/auth` · `/api/login-seq` · `/api/crawl`

### 엔드포인트 조회 API (이슈 #7)
- `GET /api/endpoints` — 필터·검색·페이징: `host`(부분일치)·`method`·`verdict`(부분일치)·
  `auth`(true/false)·`source`(등급 부분일치, 이슈 #28)·`auth_only=true`(인증 뒤 표면만, 이슈 #38)·
  `q`(host+path 검색)·`limit`/`offset`.
  `include_unverified=true`(이슈 #28)면 라이브니스 미통과 노드까지 포함(기본은 verified 만).
  전체 개수는 **`X-Total-Count`** 헤더. **무필터·무페이징이면 기존과 동일한 전체 배열**(하위호환)
- `GET /api/endpoints/tree` — 풍부한 트리(`Snapshot`): verdict·hit count·children·params
- `GET /api/endpoints/detail?host=&path=` — 단일 엔드포인트 상세(concrete path 도 정규화해 조회):
  메서드·파라미터·히트 수·판정·**최초/최근 발견 시각**

> 발견 시각(`first_seen`/`last_seen`)은 엔드포인트 모델에 저장되고 `endpoints.json`에 영속화된다
> (재시작 후에도 유지). 현재 UI 필터는 클라이언트 측에서 즉시 반영되며, 위 서버측 필터는 API·프로그램틱 조회용이다.

## 프록시 캡처 제어 (공용 :8080)

공용 프록시는 항상 켜져 있고, **엔드포인트 캡처(공격면 기록)만 런타임에 on/off** 합니다
(프로세스·스코프·인증·판단 파이프라인은 영향 없음). 캡처를 끄면 트래픽은 그대로 통과하되
`endpoints.json`에 새 엔드포인트가 기록되지 않고, 다시 켜면 재개됩니다.

- **상태 조회** `GET /api/proxy` — 리슨 주소·캡처 여부·스코프 호스트 수·누적 캡처 수·공격면 규모
- **캡처 토글** `POST /api/proxy/capture` `{on}` — 리더(`proxy:control`), 감사 기록
- **MCP** `proxy_status`(조회) · `set_capture`(토글, 리더) — 외부 에이전트용
- 테넌트 전용 프록시([02-프로젝트](02-프로젝트.md))는 이 토글의 영향을 받지 않습니다(격리 유지)

> GUI 연동 완료(이슈 #9) — 위 상태·토글은 정찰 페이지 좌측 **프록시 도구** 카드에서 바로 쓸 수 있고,
> API·MCP로도 동일하게 제공됩니다. (CA 설치는 OS 신뢰저장소 변경이라 웹에서 실행 불가 → 명령 안내로 제공)

## 인증 델타 크롤 (이슈 #38)

로그인 뒤에만 접근 가능한 표면(관리 기능·내 정보·주문)은 **접근통제 취약점의 핵심 무대**입니다.
KII·전자금융 규제의 수평/수직 접근통제 점검항목과 직결됩니다. 인증 델타 크롤은 같은 대상을
**비인증 → 인증** 두 번 크롤해, 인증 뒤에만 접근되는 표면을 `auth-only` 로 표시합니다.

- **옵트인**: `Options.AuthDelta`. 인증 설정(로그인 시퀀스 또는 정적 쿠키/헤더, #31)이 있을 때만
  두 패스를 돈다. 없으면 일반 크롤로 fallback.
- **두 패스**: 크롤러가 비인증 패스(인증 주입 안 함) → 재로그인 → 인증 패스 순으로 한 실행에서 돈다.

### 판정 — "2xx 접근 성공" 기준

`auth-only` 는 **경로 존재**가 아니라 **접근 성공** 기준입니다. 링크는 인증/비인증 양쪽에 다 있어도,
비인증에선 401 을 받으면 접근 못 한 것입니다.

```
auth-only = 인증 패스에서 2xx 로 접근된 경로  −  비인증 패스에서 2xx 로 접근된 경로
```

vulnapp 실측:

| 경로 | 비인증 | 인증 | auth-only |
|---|---|---|---|
| `/orders`·`/profile`·`/dashboard` | 401 | 200 | ✅ 인증 뒤에만 접근 |
| `/admin` | **200** | 200 | ❌ 비인증에도 뚫림(접근통제 취약) |

`/admin` 이 auth-only 가 **아닌** 것이 중요합니다 — "숨겨진 표면"과 "인증 없이 뚫리는 표면"은
다릅니다. 후자는 그 자체가 접근통제 결함이라 인증 뒤 표면과 섞이면 안 됩니다.

### 출처와 직교하는 별도 플래그

`auth-only` 는 출처 등급(#26)이 아니라 **직교 속성**입니다(`node.authOnly`, #26 `unverified` 와 같은
패턴). 한 엔드포인트는 `crawl-link` 이면서 동시에 `auth-only` 일 수 있습니다 — "어떻게 발견했나"(출처)와
"인증 뒤인가"(속성)는 다른 축입니다.

- Endpoint Tree 행에 **`auth-only` 배지**(빨강) + **"인증 뒤 (N)" 필터**(#28 프레임).
- API: `GET /api/endpoints?auth_only=true` 로 인증 뒤 표면만.
- 벤치 하네스: `auth-delta` 프로파일(로그인 설정이 있는 대상만).

재현:

```bash
cd backend && go test ./internal/crawler -run AuthDelta -v
```

## 능동 콘텐츠 발견 (이슈 #27)

링크·명세·트래픽 어디에도 안 걸리는 **unlinked 공격면**이 있습니다 — 백업 파일·`.git`·설정·로그
디렉터리·관리 화면. Juice Shop 실측 기준 `/support/logs`·`/encryptionkeys` 는 **디렉터리 목록이
그대로 열려 있는데도** 링크가 없어 크롤·인제스트로는 영원히 못 찾습니다. 능동 발견은 알려진 관례
경로 목록(wordlist)을 직접 찔러 실재하는 것만 등록합니다.

### ★ 기본 비활성 (옵트인)

능동 탐색은 **파괴성·소음·법적 경계**가 있어 안전장치가 전제입니다. `Options.Discover` 를 켜야만
요청이 나가고, **켜지 않으면 한 건도 나가지 않습니다**(테스트로 고정). 웹 API 는 `POST /api/crawl` 의
`discover` 파라미터로 켜며, 켜면 일반 crawl 감사에 더해 `crawl:discover` 감사 기록이 따로 남습니다
— 누가 언제 켰는지, wordlist 몇 항목에 예산 몇 건이었는지.

| 안전장치 | 내용 |
|---|---|
| 옵트인 | `Discover=false` 가 기본. 켜지 않으면 프로브 0건 |
| GET only·비파괴 | wordlist 에 상태를 바꿀 경로(`/logout`·`/reset` 류)를 넣지 않음 |
| 스코프 하드 | `scope.Allowed` 로 게이트 (FR-2.1) |
| 레이트리밋 | 크롤러와 같은 120ms/건 |
| 요청 예산 | 기본 500건(약 1분). 소진 시 중단하고 `Report.Exhausted` 로 "부분 확인"을 남김 |
| 감사 | `crawl:discover` 기록 |

### wordlist

`internal/recon/discover/wordlist.txt` 에 `go:embed` 로 넣어 폐쇄망 단일 exe 를 유지합니다.
**자체 작성**이라 외부 라이선스 제약이 없고, 154항목 / 2.7KB 로 embed 부담도 없습니다. 분류별로
묶여 있습니다 — VCS 노출(`.git/*`)·설정/시크릿(`.env`·`config.*`)·백업(`backup`·`*.sql.zip`)·
관리 화면(`admin`·`phpmyadmin`)·로그/진단(`logs`·`phpinfo.php`)·API/명세·파일 저장소·앱 메타.

### 판정은 라이브니스(#26)와 공유한다

같은 soft-404 캘리브레이션을 씁니다(`internal/recon/probe`). 존재할 리 없는 경로로 기준 지문을
잡고, 후보 응답이 같은 모양이면 실재하지 않는 것으로 봅니다. `/admin` 은 Juice Shop 에 **없지만**
SPA catch-all 이라 200 을 주는데, 이렇게 걸러집니다:

```
baseline                  200  text/html  9393B
/admin  /.git/config  /.env  /backup      → 전부 200 9393B (= baseline) → 버림
/support/logs             200  text/html  8891B  → 다름 → 등록
```

라이브니스와 다른 점 두 가지:

- **등록 전에 판정합니다.** 라이브니스는 "일단 등록 후 강등"이지만 discover 는 실재를 확인한
  뒤에만 넣습니다 — 트리에 쓰레기를 넣었다 지우는 것보다 낫고 `unverified` 노드가 쌓이지 않습니다.
- **5xx 를 버립니다.** Juice Shop 은 없는 API 베이스 경로에 `500 "Unexpected path: /api"` 를 주는데,
  이건 엔드포인트가 아니라 "그런 경로 없음"의 다른 표현입니다. 라이브니스는 반대로 5xx 를 살립니다
  (우연히 터진 실 엔드포인트를 강등하면 재현율 손실) — **두 기능의 리스크 방향이 반대**라 그렇습니다.

### 출처 등급

등록분은 `source=discover` 로 태깅됩니다. 등급은 6단계가 됩니다:

```
spec > traffic > headless-xhr > discover > crawl-link > static-regex
```

discover 는 "**실재는 확실하나 실제로 쓰이는지는 모른다**"이므로 앱이 스스로 호출하는 XHR 보다
아래, 링크가 가리키는 것보다 위입니다. **등록 전에 이미 실재를 확인했으므로 라이브니스 재프로브
대상이 아닙니다**(`NeedsProbe`=false) — 안 그러면 방금 찾은 것을 또 찌릅니다.

재현:

```bash
cd backend && go test ./internal/recon/discover -v
```

## 라이브니스 검증 · 출처 신뢰도 (이슈 #26)

크롤러가 JS 번들에서 정규식으로 긁어온 경로에는 **실재하지 않는 것**이 섞입니다 — i18n 키·CSS
경로·SPA 클라이언트 라우트가 그대로 스캔 대상이 되면 오탐과 낭비를 만듭니다. Juice Shop `static`은
페이지를 3개만 가져왔는데 엔드포인트 84개를 발견했고 그중 71건(83.5%)이 오탐이었습니다.

### 출처 신뢰도 등급

엔드포인트마다 **어디서 알게 됐는지**를 기록하고, 믿을 수 없는 출처만 실재 여부를 확인합니다.

| 등급 | 의미 | 프로브 |
|---|---|---|
| `spec` | 명세 인제스트 (#25) | 면제 |
| `traffic` | 프록시 실캡처 — 외부에서 들어온 트래픽 | 면제 |
| `headless-xhr` | 헤드리스가 캡처한 XHR/fetch — 앱이 스스로 호출 | 면제 |
| `crawl-link` | 크롤러가 따라간 링크 | **대상** |
| `static-regex` | JS/HTML 정규식 추출물 | **대상** |

**"실제로 요청해서 2xx를 받았다"와 "실재한다"는 다릅니다.** SPA는 없는 경로에도 200을 주므로,
크롤러가 스스로 만들어낸 요청(링크 추종·정규식 추출)은 따로 확인해야 합니다. 반대로 외부에서
들어온 트래픽과 앱이 스스로 호출한 XHR은 실재의 증거 자체라 면제합니다.

출처를 남기지 않던 시절의 값(`""`)은 프록시 캡처의 기본값이라 `traffic`과 같은 등급으로 봅니다.
노드가 병합될 때는 **더 높은 등급이 이깁니다**.

### soft-404 판정

상태코드로는 판정할 수 없습니다. 그래서 먼저 **존재할 리 없는 경로 2개로 baseline**을 잡고,
후보 응답이 그 baseline과 같은 모양(상태코드 · content-type · 본문 해시/길이 ±2%)이면
실재하지 않는 것으로 봅니다.

| 응답 | 판정 |
|---|---|
| 404 / 410 | 강등 |
| **401 / 403** | **실재** — 인증 벽 뒤 엔드포인트입니다 |
| 5xx | 실재 — 서버 오류는 부재의 증거가 아닙니다 |
| 3xx | 실재 |
| 2xx + baseline과 같은 모양 | 강등 (soft-404) |

판정을 포기하는 경우도 둘 있습니다. **정직하게 404를 주는 서버**는 baseline이 필요 없고,
**응답이 매번 다른 서버**는 비교가 불가능하므로 아무것도 강등하지 않습니다. 근거 없는 강등은
하지 않습니다.

`HEAD` 대신 `GET`을 씁니다 — soft-404는 본문 비교가 필요한데 HEAD는 본문도 `Content-Length`도
없을 수 있습니다. 본문을 1MB로 자르고 크롤러와 같은 120ms 레이트리밋을 겁니다.

**루트 경로(`/`)는 강등하지 않습니다.** SPA 셸 HTML은 곧 `/`의 진짜 내용이라 baseline과 같은
모양으로 보이는데, 서버가 응답한 이상 루트는 실재합니다. 여기서 걸러내면 크롤 시작점이 사라집니다.

### 삭제가 아니라 강등

실재가 확인되지 않으면 트리에서 지우지 않고 **`unverified` 플래그만** 세웁니다. 지우면 왜
제외됐는지 근거가 사라져 재현할 수 없기 때문입니다.

- `endpoints.Targets()` — `unverified`를 **기본 제외**합니다(스캔 대상에서 빠짐)
- `endpoints.TargetsAll()` — 강등분까지 전부. 진단·감사용
- 강등된 노드가 나중에 **면제 등급으로 다시 잡히면 복구**됩니다(실 트래픽이 왔다 = 실재한다)

### 언제 도는가

크롤(`static`/`headless`)이 끝나면 자동으로 1회 검증합니다. `Options.NoVerify`로 끌 수 있고,
결과는 `Result.Demoted`(강등 수)로 보고됩니다.

재현:

```bash
cd backend && go test ./internal/recon/liveness -v
```

## 스펙 인제스터 (이슈 #25)

링크를 따라가는 크롤만으로는 **링크가 없는 API**를 찾을 수 없습니다. VAmPI 같은 순수 REST API는
크롤 재현율이 0%였습니다. 인제스터는 대상이 **스스로 공개하는 명세**를 읽어 엔드포인트를 얻습니다
(`backend/internal/recon/ingest/`). OpenAPI 한 파일이면 수백 페이지 크롤보다 정확한
경로·메서드·파라미터·타입을 한 번에 줍니다. Chrome이 필요 없어 **폐쇄망 정적 SPA 대응의 핵심**이기도 합니다.

| 수집기 | 대상 | 얻는 것 |
|---|---|---|
| robots.txt | `/robots.txt` | `Allow`/`Disallow` 경로 (와일드카드 규칙 제외) |
| sitemap.xml | robots의 `Sitemap:` 또는 `/sitemap.xml` | `<loc>` 경로. `sitemapindex` 중첩 재귀(깊이 3) |
| OpenAPI/Swagger | 후보 8종 프로브 | paths·methods·parameters·requestBody (타입·required 포함) |
| GraphQL | `/graphql` 계열 3종 | introspection 성공 시 경로를 공격면으로 등록 |
| 소스맵 | `<script src>` + `.map` | 파일 단위 복원 후 API 경로 + 프레임워크 라우트 추출 (이슈 #39) |

전부 **GET only·비파괴**이며 스코프(FR-2.1)로 하드 게이트하고, 크롤러와 같은 120ms 레이트리밋과
인증 주입(FR-2.5)을 씁니다. 명세가 스스로 선언한 경로(robots·sitemap·OpenAPI·GraphQL)는
`RecordSpec`으로 **출처 `spec`**(프로브 면제) 태그가 붙고, 소스맵 본문에서 정규식으로 추측한 경로만
**`static-regex`**(라이브니스 검증 대상)로 등록됩니다 — 아래 소스맵 절 참조.

### 상태코드로 판정하지 않습니다

SPA는 **없는 경로에도 `index.html`을 200으로** 돌려줍니다. Juice Shop 실측:

```
/openapi.json                -> code=200 type=text/html size=9393
/swagger.json                -> code=200 type=text/html size=9393
/graphql                     -> code=200 type=text/html size=9393
nonexistent-bogus-xyz.js.map -> code=200 type=text/html size=9393
```

상태코드만 보면 **없는 명세 4개를 "발견"하고 HTML을 파싱하려 듭니다.** 인제스터는 content-type과
본문의 필수 키까지 확인합니다 — OpenAPI는 `paths` + 버전 표식(`openapi`/`swagger`), GraphQL은
`data.__schema`, 소스맵은 `version` + `sources`. 걸러낸 후보는 `Report.Rejected`에 남아
"검증이 실제로 동작했다"를 확인할 수 있습니다.

소스맵 발견도 `sourceMappingURL` 주석에 의존하지 않습니다. Juice Shop 번들은 그 주석이 제거돼 있어
주석만 믿으면 하나도 못 찾습니다. 주석이 있으면 우선하고, 없으면 **`<번들>.map` 관례로 프로브**합니다.

### 소스맵 완전 복원 — 파일 단위 라우트 추출 (이슈 #39)

이전에는 `sourcesContent`를 전부 이어 붙여 `/api·/rest·/vN·/graphql` 정규식 하나만 돌렸습니다.
API 스타일 경로는 잡지만 **클라이언트 라우트 정의**(React Router·Vue Router·Angular RouterModule)는
통째로 놓쳤습니다. Juice Shop의 `/administration`·`/score-board` 같은 화면은 링크가 아니라 라우트
설정에만 있어, 크롤·API 추출 어느 쪽으로도 안 걸립니다.

`parseSourceMap`이 이제 `sources`(파일명)와 `sourcesContent`(본문)를 **인덱스로 짝지어** `SourceFile`
목록을 돌려줍니다. 파일 단위 분석이 두 가지를 가능케 합니다.

- **프레임워크 라우트 추출** — `path: '...'` / `path="..."` 프로퍼티를 정규식으로 뽑아 정규화합니다:
  `:id`→`{id}`(트리 변수 자리 규칙), 상대 경로 앞 `/` 보정(Angular 자식 라우트), 와일드카드(`*`·`**`)
  자리에서 절단, 외부 URL·템플릿 보간(`${...}`)·표현식 제외.
- **벤더 파일 제외** — `node_modules`·번들러 런타임 파일은 라우트 추출에서 뺍니다. 라이브러리 내부
  라우터 코드에 `path:`가 많아 통째로 뽑으면 오탐이 쏟아지는데, 파일 경로로 걸러냅니다.
  API 경로 추출은 프리픽스 앵커라 노이즈가 적어 벤더 포함 전체에서 돌립니다.

### 소스맵 추출물은 `static-regex` — 라이브니스 검증 대상

명세(OpenAPI/robots/sitemap/GraphQL)는 대상이 **스스로 선언한** 정보라 `spec`(프로브 면제)입니다.
반면 소스맵 본문에서 **정규식으로 추측**한 경로는 실재 보장이 없습니다 — 상대 라우트를 절대 경로로
오인하거나, 죽은 라우트가 남아 있을 수 있습니다. 그래서 소스맵 추출물은 `RecordSpec`이 아니라
`RecordFrom(static-regex)`로 등록해 **라이브니스(#26) 프로브 대상**으로 만듭니다. Juice Shop static
실측에서 정규식 추출의 81%가 오탐이었고, 이 등급 지정이 그 오탐을 트리에서 걸러냅니다.

### 명세 경로와 크롤 경로는 한 노드로 합쳐집니다

명세는 `/users/v1/{username}`을, 크롤은 `/users/v1/alice`를 등록합니다. 그대로 두면 같은 엔드포인트가
노드 2개로 갈라져 트리가 중복 계상되고, 크롤 쪽 노드는 `source=spec` 태그를 못 받습니다.

`RecordSpec`이 경로에서 `{name}` 세그먼트를 만나면 **그 자리를 "변수 자리"로 선언**합니다
(아래 경로 정규화 v2 절의 형제 클러스터링과 같은 흡수 메커니즘). 이후 크롤이 같은 자리에 구체값을
기록하면 별도 노드를 만들지 않고 흡수됩니다.

흡수 규칙은 세 가지를 지킵니다.

- **리터럴 우선.** 명세가 `{username}`과 `_debug`·`register`·`login`을 함께 등록했을 때, 크롤이 만난
  `/users/v1/_debug`가 `{username}`으로 삼켜지면 안 됩니다.
- **명세 선언 자리는 값 모양을 따지지 않습니다.** 휴리스틱(#24)은 숫자·구분자가 있는 세그먼트만
  흡수하지만, 명세는 확정 정보이므로 `alice`도 흡수합니다.
- **명세 기록 자신은 흡수되지 않습니다.** 명세가 트리 구조의 기준입니다.

### 언제 도는가

크롤(`static`/`headless`)을 시작하면 **seed 호스트에 대해 1회 자동 인제스트**합니다. 링크를 따라가기
전에 명세를 먼저 확보해야 이후 크롤이 만나는 구체값이 변수 자리로 흡수됩니다. `Options.NoIngest`로 끌 수 있습니다.

벤치 하네스에는 **`ingest` 프로파일**이 따로 있습니다. 크롤을 돌리지 않아 "명세만으로 얼마나 찾는가"가
그대로 측정됩니다. 실측 결과는 `docs/recon-groundtruth/README.md`를 보세요.

재현:

```bash
cd backend && go test ./internal/recon/ingest -v
```

## 경로 정규화 (v2, 이슈 #24)

같은 엔드포인트가 값만 다른 수백 개 노드로 쪼개지면 트리가 폭발하고 스캔 타겟·커버리지
지표가 오염됩니다. Endpoint Tree는 경로를 기록하기 전에 **가변 세그먼트를 템플릿으로 접습니다**
(`backend/internal/endpoints/normalize.go`).

| 입력 세그먼트 | 접힌 결과 | 예 |
|---|---|---|
| 숫자만 | `{id}` | `/user/42` → `/user/{id}` |
| UUID (8-4-4-4-12) | `{uuid}` | `/u/550e8400-…-446655440000` → `/u/{uuid}` |
| hex 16자 이상 | `{hash}` | `/t/0123456789abcdef0123` → `/t/{hash}` |
| `YYYY-MM-DD` | `{date}` | `/logs/2026-08-18` → `/logs/{date}` |
| base64-ish (20자↑·숫자·대문자) | `{b64}` | `/t/eyJhbGciOiJIUzI1NiJ9` → `/t/{b64}` |

- **확장자는 보존**하고 파일명 안의 해시만 접습니다 — `/assets/main.9f8a7b6c5d4e3f21.js` → `/assets/main.{hash}.js` (웹팩 번들 해시).
- hex는 **16자 이상**만 변수로 봅니다. `/x/cafe` 같은 짧은 hex는 실단어일 수 있어 보존합니다.
- base64는 소문자 slug(`application-configuration`)와 구분하려고 숫자·대문자를 함께 요구합니다.

### 형제 다양성 클러스터링

같은 부모 밑에 값처럼 생긴 리프가 **12개 이상** 쌓이고 **고유비율이 0.8 이상**(대부분 1회만 등장)이면
그 자리는 라우트명이 아니라 값이라고 보고 `{slug}` 하나로 병합합니다. 한 번 접힌 자리는 이후 값을
바로 흡수해 재팽창을 막습니다.

접기 대상에서 **제외**되는 것 — 재현율(공격면 누락)을 보호하기 위한 보수적 경계입니다.

- **호스트 루트 직속 자식**. 루트 세그먼트는 대개 최상위 라우트명이라, 접히면 `/metrics` 같은 실제 엔드포인트가 통째로 사라집니다.
- **파라미터가 있는 노드**. 공격면 자체이므로 보존합니다.
- **하위 구조가 있는 노드**. 리프만 후보입니다.
- **값처럼 생기지 않은 세그먼트**. 숫자를 포함하거나 단어 구분자(`-` `_`)가 2개 이상인 것만 후보입니다. 라우트명은 대개 한 단어이거나 하이픈 하나로 이어진 짧은 명사구입니다 (`Products`, `SecurityQuestions`, `application-configuration`, `reset-password`).

> **이 가드가 없으면 REST 리소스 컬렉션이 통째로 사라집니다.** Juice Shop `/api` 밑에는
> `Products`·`Feedbacks`·`Challenges` 등 12종 이상이 각각 1회씩만 등장하는 리프로 쌓입니다.
> "리프 + 무파라미터 + 고유비율 높음"만으로는 이들이 slug 값과 구분되지 않아 `/api/{slug}` 하나로
> 접혔고, 하네스 재현율이 41.9% → 22.6%로 무너진 적이 있습니다.

### 하위호환

v1(숫자만 접던 시절)로 저장된 `endpoints.json`은 **로드 시 1회 재분류·병합**됩니다. 같은 템플릿이 된
노드는 히트 수(`count`)와 파라미터 등장 수(`seen`)를 합산해 `Required`(= `seen == count`) 정합을
유지하고, 재요청용 구체 경로는 더 최근에 본 쪽을 남깁니다. 파일은 다음 캡처 때 자연히 갱신됩니다.

`Param.Type`의 반환 집합은 v1 그대로입니다(`int|bool|uuid|email|string`) — 분류 **규칙**만
공유하고 저장·표시 계약은 바꾸지 않습니다.

재현:

```bash
cd backend && go test ./internal/endpoints -run Normalize -v
```
