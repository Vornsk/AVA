# 04 · 스캔 / 자동화 진단 (Scan)

> 사이드바 **진단 > 스캔** · 소스 `frontend/src/pages/Scan.tsx` · 실행·제어는 `scan:run` 권한

파악된 공격면을 대상으로 **탐지기를 선택해 자동 진단**을 실행하고, 실행 중인 스캔을 제어하는
페이지입니다. 요구사항 §5.3(자동화 진단)·FR-3.x에 대응합니다.

## 화면 구성

- **스캔 시작 (ScanControl)** — **모드 탭** 두 가지:
  - **수동 선택** — 탐지기 체크박스 그리드(전체선택/해제, 파괴적 `D` 배지, 외부도구 미설치 표시).
    기본 선택에서 `sqli-time` 은 제외된다(시간 기반 블라인드라 스캔이 크게 느려짐 — 전체선택으로는 켤 수 있음).
  - **AI 추천 (ScanRecommend)** — 엔드포인트마다 관련 탐지기를 LLM 이 추천한다(HITL). 실행 전
    **반드시 검토·수정**해야 계획이 전달된다. 프로바이더 장애 시 기본값(비파괴 전체)으로 폴백.
  옵션 토글:
  - **LLM 오탐 검토** — 각 finding을 LLM이 증적으로 검토·주석(상태는 안 바꿈, HITL)
  - **파괴적 포함** — `file-upload` 등 부작용 가능한 탐지기 포함(opt-in)
  - **LLM 판단 상태·정책** (이슈 #56·#62) — 카드 하단에 판단 스테이지 상태를 한 줄로 노출한다:
    프로바이더 이름 · **판단 불능 배지**(degraded 시 빨강, 누적 건수·사유) · **fail-open/closed 토글**
    (`통과`/`차단`, 리더만 변경 — 비리더는 현재값 배지). "LLM 검토를 켜는 사람은 지금 판단이
    살아있는가 + 죽으면 어떻게 되는가를 같은 자리에서 봐야 한다"가 이 배선의 취지.
- **실시간 로그 (ScanLogPanel, 이슈 #59)** — 실행 중인 스캔의 **요청 단위 로그를 SSE 로 실시간**
  스트리밍한다(발견은 빨강 강조, 탐지기 태그 표시). 진행 중 run 이 없으면 직전 완료 run 의 로그를
  재생(서버가 재시작 전까지 메모리 보관) — 새 스캔 시작 전까진 사라지지 않는다.
- **Scan Runs (FR-3.8)** — 실행 목록(ID·상태·탐지기·건너뜀·진행률·findings·safe). 각 행에서
  **일시정지 / 재개 / 취소** 제어(상태별 노출, 취소는 confirm). 상태 색상: 진행=blue·일시정지=amber·
  완료=green·중단=muted. 2초 폴링
- **Detectors 카탈로그** — 탐지기 26종 목록(내장/외부도구, 파괴적 표식, 외부도구 ready/missing·버전)
- **가드레일** — Safe mode · Destructive opt-in · rate-limit(safe 500ms / 일반 150ms) · kill-switch
- **페이로드** — 페이로드 버전, XSS 페이로드, 한국형 민감정보 패턴
- **외부 도구** — openssl/sslscan 설치·버전 상태

## 주요 액션 → API

| 액션 | 엔드포인트 |
|---|---|
| 스캔 시작 | `POST /api/scan` (`detectors[]`, `per_target`, `allow_destructive`, `llm_review`) |
| 탐지기 AI 추천 | `POST /api/scan/recommend` — 대상별 탐지기 추천(LLM, HITL 검토용) |
| 실시간 로그 스트림 | `GET /api/scanruns/{id}/log/stream` — SSE(이슈 #59) |
| 일시정지/재개/취소 | `POST /api/scanruns/{id}/pause` · `/resume` · `/cancel` (멱등 가드, 완료·중단이면 409) |
| 판단 불능 정책 조회/변경 | `GET`·`POST /api/judge-on-error` (`policy` = allow 또는 block, `llm:policy` 리더, 이슈 #56·#62) |

조회: `/api/scanruns` · `/api/detectors` · `/api/stats`(`llm_health` 포함) · `/api/payloads` · `/api/endpoints`

## LLM 판단 정책 — fail-open / closed (이슈 #56)

프로바이더 장애는 **판단 불능**이지 **안전 판정**이 아닙니다. 세 실패 경로가 조용히 통과시키고
그 판정이 캐시에 고착돼 프로바이더가 살아나도 안 돌아오던 문제를 #56 이 고쳤습니다.

- **fail-open (`allow`, 기본)** — 판단 불능 시 요청을 통과시킵니다. 진단 대상 서비스를 죽이지 않는
  것이 이 도구의 1원칙이라, 스캔 도중 ollama 가 죽었다고 진단이 통째로 멈추면 그게 더 큰 사고입니다.
- **fail-closed (`block`)** — 판단 불능 시 차단합니다. 운영 결제계처럼 "막지 못할 바엔 보내지 않는다"가
  맞는 대상용. **프로젝트별**로 고르며 활성 프로젝트에 영속화됩니다(재기동·재활성화에도 유지).
- **가시화** — fail-open 이 발동해도 화면·로그가 멀쩡해 보이던 문제를, 상태 전이를 감사 로그와
  GUI(스캔 페이지 LLM 배지·Overview 배지)에 드러내 해결했습니다. 상태는 `GET /api/stats` 의
  `llm_health`(degraded·count·reason·policy)로 노출됩니다.

## LLM 오탐 트리아지 (이슈 #54)

`llm_review` 를 켜면 각 finding 을 LLM 이 증적과 함께 검토해 오탐 여부를 주석합니다(판정은 상태를
바꾸지 않음, HITL). 트리아지 프롬프트는 detector 별 맥락을 자동 생성하고 정탐/오탐 힌트를 대칭으로
제시합니다 — "오탐 조건만 나열하고 정탐 조건을 안 적으면" 모델이 정탐까지 지운다는 실측(스캔 벤치)에서
나온 규율입니다. 트리아지 모델 권장·정탐 손실 측정치는 [`docs/scan-groundtruth/README.md`](scan-groundtruth/README.md).

## 동작 메모
- 스캔은 **비동기**입니다. 여러 run이 동시에 돌 수 있으니 finding 조회 전 **모든 run이 '완료'인지** 확인.
- `sqli-time`은 시간지연을 유발해 느립니다(2회 확증). 완료까지 대기 필요.

## 스캔 품질 벤치 (이슈 #49)

detector 를 고치거나 추가할 때 **"좋아졌다 / 회귀 없다"를 숫자로** 말하기 위한 계기판입니다.
정찰 벤치(#22)가 정찰에 해준 것을 스캔에 합니다.

```bash
cd backend && go test ./internal/scanengine/bench -run ScanBench -v -count=1
```

> `-count=1` 을 꼭 붙이세요. 정답셋 YAML 이 패키지 밖에 있어 go test 캐시가 변경을 감지하지
> 못합니다 — 빼먹으면 YAML 을 고쳐도 이전 결과가 그대로 재출력됩니다.

`vulnlab` 은 `httptest` 로 인프로세스 기동돼 준비 없이 항상 채점됩니다.
`vulnapp` 은 `go run ./cmd/vulnapp` 으로 띄워야 하고, 미기동이면 skip 됩니다.

### 무엇을 재는가

정답셋(`docs/scan-groundtruth/*.yaml`)의 대상으로 엔드포인트를 **직접 시드**하고 크롤은 돌리지
않습니다 — 정찰이 못 찾은 경로가 스캔의 FN 으로 잡혀 detector 탓이 되는 것을 막습니다.

- **TP** = `expect` 조합 발견 · **FP** = `not_expect`(정상 구현) 조합 발견
- **미분류** = 정답셋에 없는 발견. **오탐으로 세지 않습니다** — 정답셋을 넓히라는 작업 목록입니다
- **측정불가** = 담당 detector 가 파괴성 등으로 빠진 정답. GT 분모에서 제외합니다
- detector 별 TP/FP 분해로 **어느 탐지기가 오탐을 만드는지** 지목합니다

수치와 채점 규칙 상세, 정답셋 작성법은 [`docs/scan-groundtruth/README.md`](scan-groundtruth/README.md).
