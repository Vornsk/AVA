## 1. 설계 배경 & goproxy 선택

상위 폴더(`../`)에 세 개의 한글 설계 문서가 있습니다:

| 문서 | 목적 |
|---|---|
| `취약점진단도구_요구사항_아키텍처_정의서.md` | 전체 요구사항 & 아키텍처 |

| `취약점진단도구_프록시 전략 및 추진 계획.md` | 프록시 결정 + 추진 계획 |

**문서 권고:** *세미커스텀* 프록시 — 검증된 TLS 엔진을 재사용하고 판단 로직만 직접 구현.
1순위는 mitmproxy, goproxy는 단일 바이너리 배포가 꼭 필요해질 때 대비.

**실제 선택(의도적 편차):** 배포가 **단일 Go 바이너리**로 기우는 만큼 **goproxy**를 코어로
직접 검증. mitmproxy 폴백은 열어둠.

### 두 계층 (경쟁 아님)

```
┌─────────────────────────────────────────────┐
│  오케스트레이션 계층 (LLM 주도) = MCP        │  ← 공격면 조회 / 스코프·스캔 제어
├─────────────────────────────────────────────┤
│  코어 엔진 (goproxy)                          │  ← 가로채기 + 스코프 + 마스킹 + 공격면
└─────────────────────────────────────────────┘
```

판단 파이프라인(스코프/마스킹)은 가로채는 지점에서 **인라인**으로 돌아 스코프 밖으로 아무것도
안 나갑니다. MCP는 그 위에서 LLM이 조회·제어하는 계층.

### 왜 Burp가 아니라 Go-native MCP인가 (중요 발견)

당초 Burp의 공식 MCP 확장을 붙일 계획이었으나 **이 머신에서 실행 불가**입니다. Burp MCP
확장(JVM/Netty)이 기동 시 `failed to create a child event loop`로 죽습니다. 근본 원인:

- JVM의 NIO `Selector`가 내부 self-pipe를 **AF_UNIX(유닉스 도메인 소켓)** 로 만드는데,
  이 머신은 **AF_UNIX `connect`가 전역으로 실패**합니다(`connect: Invalid argument`).
  번들 OpenJDK와 별도 Go 프로그램 양쪽에서 재현. `listen`/`bind`는 되고 `connect`만 실패 —
  보안 소프트웨어/Winsock-LSP 간섭(보안 워크스테이션의 의도적 하드닝 추정).

**결론 & 교훈:** 이 폐쇄/보안 환경에서 JVM-NIO·AF_UNIX 기반 IPC는 불안정. **Go + TCP가 더
견고**합니다(Go의 Windows 런타임은 IOCP+TCP를 쓰고 AF_UNIX를 안 씀). goproxy 선택을 강화하는
근거. Burp MCP를 나중에 쓰려면 머신을 고치거나(`netsh winsock reset`+재부팅) 다른 호스트에서
실행해야 합니다.

## 2. 판단 파이프라인

**스코프(host+path) → [설정된 스테이지: Rule → LLM] → (전송 + 캡처)**

- **스코프(FR-2.1):** 화이트리스트 밖 host/path는 하드 차단. 프록시·크롤러·스캔 모두 공유.
- **Rule 스테이지(FR-2.2):** 결정론적 룰로 위험/파괴적 요청을 전송 전 차단(logout·DELETE·
  삭제성·admin·결제확정). `recon_allow`로 접근통제 점검 시 관리자 경로 recon만 허용.
- **LLM 스테이지(§5.2):** Rule이 `llm`으로 표시한 상태변경 요청을 LLM이 allow/block 판단.
  입력 토큰 최소화(정규화 path + 파라미터 키만), 판정 캐싱·로깅. 프로바이더 교체형
  (`mock|ollama|anthropic|openai`).

판정 기록은 [룰 제안](09-룰제안.md) 페이지에서 룰 이관 후보의 근거가 됩니다.

## 3. 자동 진단 (탐지기 25종 + 데모)

내장 23종 + 외부도구 2종. 규제 점검항목표에 매핑됩니다(→ [커버리지](06-커버리지.md)).

- **기본/정보노출:** `security-headers`(보안헤더 누락) · `sensitive-data`(한국형 RRN/카드
  [Luhn 검증]/여권/계좌[날짜·전화 오탐 배제])
- **XSS 3형태:** `reflected-input`(반사형, **컨텍스트 인식** — 실행 가능 위치만) ·
  `stored-xss`(저장형, 고유 마커가 **클린 재조회에 반사**되면 확정 · 파괴적/옵트인) ·
  `dom-xss`(source→sink **정적 힌트**). **DVWA `xss_r`/`xss_s`/`xss_d` 실앱 검증 완료**
- **접근통제:** `idor`(수평/미인증노출) · `privesc`(수직 권한상승) — 차등 분석, 동적 콘텐츠
  정규화로 견고
- **인젝션(공격형):** `sqli`(에러) · `sqli-blind`(불린) · `sqli-time`(시간지연, **2회 확증**) ·
  `path-traversal` · `open-redirect` · `cmd-injection` · `ssrf` · `ssti` · `xxe` ·
  `ldap-injection` · `ssi-injection` · `csrf`(수동적 분석) · `file-upload`(파괴적, 옵트인).
  쿼리·폼바디·JSON(중첩 포함) 모두 주입
- **설정 점검:** `cookie-security`(쿠키 속성) · `http-method`(위험 메서드) · `dir-indexing`
- **외부 도구(FR-3.4):** `openssl-tls` · `sslscan` (없으면 우아하게 skip)
- **가드레일(FR-3.2):** 파괴적 탐지기 기본 제외(`allow_destructive` 옵트인) · rate-limit ·
  safe-mode · 긴급 kill-switch
- **증적(FR-4.2):** 각 finding에 재현 요청 + 증명 응답 스니펫 + 상태코드(마스킹)
- **비동기 잡(FR-3.8):** 진행률·일시정지·재개·취소

각 탐지기는 **정탐 + 오탐 회피 대조 테스트**로 검증합니다(반사 XSS는 실행 컨텍스트만·textarea/
인코딩 반사 무발동, 저장형은 반사형만인 경우 무발동, DOM은 sink만이면 무발동, 카드는 Luhn 유효만,
CSRF는 토큰 있으면 무발동). 인젝션 계열은 실앱(DVWA + 자체 `vulnlab`)으로 정탐 검증했습니다.

## 6. 프로젝트 구조

루트는 **`backend/`**(Go)와 **`frontend/`**(React) 두 갈래. 프론트는
`backend/internal/webui/dist`로 빌드되고 Go가 `//go:embed` → 런타임 단일 바이너리.

```
proxy-poc/
  frontend/                React + TS + Vite + Tailwind (읽기전용 GUI)
    src/pages              개요/프로젝트/정찰/스캔/취약점/커버리지/리포트/이행점검/룰제안/감사/사용자
  backend/                 Go 모듈 (proxypoc)
    cmd/
      proxy/main.go        진입점: 조립 + 서빙 (프록시 + MCP + 웹GUI)
      vulnapp/main.go      의도적 취약 테스트앱 (정탐/오탐 대조 검증용, :9099)
      mcpclient/main.go    자체 MCP 서버용 데모 클라이언트
    internal/
      scope/       스코프 강제(FR-2.1) — Enforcer 인스턴스(테넌트별)
      auth/        인증 크롤링(FR-2.5) + 다중신원(FR-3.6) + 로그인 시퀀스(세션 지속성)
      rules/       Rule 스테이지(FR-2.2) + recon_allow + 채택 룰 영속화
      payload/     페이로드셋(FR-3.7) — XSS·SQLi·순회·cmd/SSRF/XXE/SSTI/LDAP/SSI·한국형 민감패턴·Luhn
      llm/         LLM 스테이지(§5.2/5.3) — Provider.Complete + Judge/Review(증적기반 오탐검토)
      masking/     민감값 마스킹(§8, FR-2.3)
      endpoints/   공격면 트리(FR-2.4) — Tree 인스턴스 + 왕복 영속화 + multipart/JSON 파라미터 캡처
      traffic/     최근 트래픽 링버퍼 — Log 인스턴스(테넌트별)
      crawler/     자동 크롤러(BFS Explore) + SPA 정적 JS 추출 + 헤드리스(chromedp) 옵트인
      ca/          전용 CA + cert-manager(FR-2.6~2.9)
      config/      계층 설정(§4) — local/project yaml 자동생성
      proxyengine/ goproxy 조립 — New(공유) / NewFor(테넌트 주입)
      tenant/      멀티테넌시(§5.1) — 프로젝트별 격리 프록시
      detector/    탐지기 25종(§5.3)
      scanengine/  스캔 오케스트레이션 — 비동기 잡·가드레일·LLM검토·영속화
      checklist/   점검항목표(§6) — 3계층 + 커버리지 + 스킴선택
      finding/     finding 저장소(§3) — 상태머신(FR-4.4) + 낙관적락(FR-1.3) + 영속화
      reverify/    이행점검(§5.5) — replay + scan diff
      advisor/     룰 제안(§5.6)
      project/     프로젝트 엔티티 + ACL(FR-1.4)
      user/session/secret/  RBAC·bcrypt·세션·AES암호화(FR-1.4)
      bundle/audit/report/coverage/  번들·감사·엑셀·커버리지
      mcpserver/   MCP 계층 (StreamableHTTP)
      webui/       웹 GUI — 요청별 인증(멀티유저) + REST 리소스
```

**민감 파일(공유/커밋 금지):** `ca.key`, `secret.key`, `users.json`, `projects.json`.
`local.config.yaml`은 PC 전용(키 보관), `project.config.yaml`은 공유 가능(스코프·룰).

의존성: `github.com/elazarl/goproxy`, `github.com/modelcontextprotocol/go-sdk`,
`github.com/chromedp/chromedp`(헤드리스 크롤 옵트인).

## 7. 빌드 & 실행

프론트를 먼저 빌드해야 합니다(출력이 Go 바이너리에 embed됨):

```bash
cd proxy-poc/frontend
npm install            # 최초 1회
npm run build          # → backend/internal/webui/dist (embed)
```

백엔드 빌드 & 실행:

```bash
cd proxy-poc/backend
go build -o proxy-poc.exe ./cmd/proxy    # 서버: 프록시(:8080) + MCP(:8765) + 웹(:8090)
./proxy-poc.exe                          # 최초 실행 시 ca.crt/ca.key 생성
```

웹 GUI: **http://127.0.0.1:8090** (다크 기본, 우상단 테마 토글). 프론트 개발 시 `frontend/`에서
`npm run dev`(Vite :5173, `/api`를 백엔드로 프록시).

프록시로 트래픽을 흘려 공격면을 채운 뒤 스캔:

```bash
curl.exe -sk -x http://127.0.0.1:8080 "https://httpbin.org/get?user=admin&password=secret" -o NUL
```

**설정(§4).** 최초 실행 시 CWD에 YAML 2개를 생성·로드(재빌드 없이 동작 변경):
- `local.config.yaml` — PC 전용: `proxy_addr`/`mcp_addr`/`web_addr`, `llm`(provider:
  `mock|ollama|anthropic|openai`, model, endpoint, api_key), `tools`(외부도구 경로),
  `safe_mode`, `auth_disabled`(개발용 로그인 우회 — 운영 금지), `artifact_ext`(DRM 비간섭 확장자).
  로컬 LLM: Ollama 설치 후 `ollama pull llama3.2:1b`, `provider: ollama`.
- `project.config.yaml` — 공유 가능: `scope`, `allow_paths`/`exclude_paths`, `recon_allow`,
  `stages`(예: `[rule, llm]`), `rules`, `auth`(인증 크롤링 쿠키/헤더), `identities`(다중신원 —
  `admin: true`로 고권한 지정), `login`(세션 지속성), `schemes`, `payloads`.

### 테스트

```bash
go test ./...            # 단위 테스트 (탐지기 정탐/오탐 대조 포함)
```

### 문서 사이트 빌드

이 문서 세트(`README.md` + `docs/*.md`)를 사이드바 탐색·다크모드가 있는 단일 HTML로 묶어

`docs/index.html`은 **생성물이므로 직접 편집하지 않습니다.** 내용을 고칠 땐 원본 `.md`를 수정한 뒤
위 명령으로 재생성하세요. 생성기는 의존성 없이 Node 16+만 있으면 됩니다(`docs/build.mjs`).

## 8. 브라우저 테스트 (실제 Edge/Chrome 프록시 경유)

1. 프록시를 한 번 실행해 `ca.crt` 생성.
2. CA 신뢰(현재 사용자 저장소, 관리자 불필요, 되돌림 가능). **보안 설정 변경이라 직접 실행**:
   ```bash
   proxy-poc.exe -cert-status      # 우리 CA가 신뢰됨? (지문 확인, 멱등)
   proxy-poc.exe -cert-install     # 사용자 Root 저장소에 설치
   proxy-poc.exe -cert-verify      # 프록시 실행 중: 경유 HTTPS로 인터셉트+신뢰 확인
   proxy-poc.exe -cert-uninstall   # 완료 후 제거
   ```
3. 프록시를 가리키는 격리 브라우저 실행(시스템 프록시 변경 없음):
   ```bash
   & "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
     --proxy-server=http://127.0.0.1:8080 --user-data-dir=$env:TEMP\edge-proxytest `
     --no-first-run --new-window https://example.com/
   ```

**보안:** goproxy 내장 CA(개인키가 GitHub에 공개됨)가 아니라 **자체 CA**를 생성합니다. `ca.key`는 비공개.

## 9. 알려진 한계 — HTTP/2 다운그레이드

goproxy의 MITM은 ALPN에서 HTTP/1.1만 광고 → **가로챈 HTTPS는 전부 HTTP/1.1로 다운그레이드**
(클라이언트↔프록시). 표준 웹앱 진단엔 문제없음(모든 요청/응답 가시·수정 가능). **미지원:**
HTTP/2 특화 테스트(h2 스머글링, HPACK), gRPC/h2-only API, HTTP/3(QUIC). 필요해지면 문서상
**mitmproxy 폴백** 트리거(h2/h3 지원).

## 10. 함정 (겪은 것들)

- **8080 포트 충돌:** Burp Suite 기본 프록시도 `127.0.0.1:8080`. Burp가 켜져 있으면 트래픽이
  Burp로 감 → 프록시가 "빈" 것처럼 보임.
- **좀비 프록시:** 백그라운드 실행이 stale `proxy-poc.exe`를 남김 → 재시작 전 `taskkill //F //IM proxy-poc.exe`.
- **AF_UNIX 전역 고장(§1):** JVM-NIO/AF_UNIX 기반 도구(Burp MCP 포함) 실패 → Go/TCP 선호.
- **실행 중 exe 덮어쓰기 불가(Windows):** 재빌드 전 프록시 종료.
- **콘솔 한글 깨짐:** 코드페이지 표시 문제일 뿐 파일은 UTF-8. 검증은 `PYTHONIOENCODING=utf-8` 등.
- **Git Bash 경로 변환:** `/`로 시작하는 curl URL을 Windows 경로로 변환 → `export MSYS_NO_PATHCONV=1`.
